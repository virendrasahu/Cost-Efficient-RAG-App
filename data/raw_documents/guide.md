# Cost-Efficient RAG Application Guide

## 1. Primary Objective
The primary objective is to design, implement, and evaluate a RAG application while avoiding high-cost always-on managed vector database pods by using embedded or self-hosted vector stores.

## 2. Idempotent Ingestion Pipeline
To prevent duplicate vector insertion during ingestion, a deterministic chunk ID is generated by computing a SHA-256 hash of the concatenation of the source path, chunk index, and chunk text content:
Chunk ID = SHA256(source_path + chunk_index + text_content).

Before upserting into the vector database, existing IDs are checked and duplicate chunks are filtered out.

## 3. Fallback Logic
When retrieved chunks have low similarity scores below the threshold (or if no chunks are returned), the system outputs a pre-defined fallback message stating: "I do not have sufficient information in the provided context to answer this question."

## 4. Embedded Vector Store
ChromaDB is used as an embedded, low-cost vector store running directly inside the application process or as lightweight disk-backed formats. It incurs zero base compute costs when idle compared to $70–$200/month for minimal managed cloud instances.
